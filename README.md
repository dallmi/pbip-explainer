# pbip-explainer

Hand over a Power BI project as a zip, get back everything needed to understand it:

- a **knowledge pack** – structured facts an agent can answer any question from (`model.json`, CSVs, `agent-brief.md`)
- **documentation** for business users and the tech team – one offline HTML file and the same content as Markdown, with an interactive data model diagram, data glossary, page-by-page description, DAX catalog with dependencies, lineage from source to visual, Power Query sources and a model health check
- **safe change impact** for every measure and column: which measures, visuals and pages change if it changes, direct and indirect, with the dependency path to each visual (e.g. `Engagement[Opens] → [Total Opens] → [Open Rate] → Card 'Open rate'`)
- **honest reference status**: report fields are *verified*, *report measure* (defined in the report), *unresolved* (not proven broken) or *observed external* (live connection); thin reports get an *observed model* reconstructed from what they use
- a **query CLI** for the questions that come up when nobody remembers how the semantic layer works: how is this measure calculated, how are these tables joined, what breaks if I change this column, what is unused
- a **desktop app** (local web UI) that does all of this by drag and drop, for one or many models
- an **analysis package** for a SharePoint folder, so a Microsoft 365 Copilot agent can answer questions about all your semantic models

## Why

Semantic models grow over years. Measures pile up, relationships get bi-directional "just to make it work", and the people who built them move on. PBIP stores the model (TMDL) and the report (PBIR) as text, so all of it can be read without Power BI – this tool does the reading and turns it into something people and agents can use.

## Install on a locked-down PC (copy and paste, no clone)

The whole tool also exists as **one file**: [`single-file/pbip_explainer.py`](single-file/pbip_explainer.py) (about 340 KB, Python 3.9+ standard library only).

1. Open the file on GitHub and click **Copy raw file**.
2. At work, create an empty file `pbip_explainer.py` (any folder, e.g. `Documents\pbip-explainer`) and paste.
3. Run `python pbip_explainer.py --make-launcher` once. It writes `start-pbip-explainer.bat` next to the file.
4. Double-click `start-pbip-explainer.bat`. Results are kept in `pbip-explainer-data` next to the file.

The same file runs the command line: `python pbip_explainer.py run Report.zip --out out\report`, `... package ...`, `... query ...`. To update, paste the new version over the old file. The file is generated by `scripts/build_single_file.py`; a test fails if it is out of date.

## Quick start – desktop app

1. In Power BI Desktop: *File › Save as › Power BI project (.pbip)*. Zip the folder that holds `X.pbip`, `X.SemanticModel/` and `X.Report/`.
2. Double-click `start.bat` (Windows) or `start.command` (macOS). A console window opens and the browser shows the app.
3. Drop the zip on the page. The documentation appears in the app, with tabs for *Documentation*, *Ask* and *Health*, and export buttons for HTML, Markdown, the model diagram (SVG) and the knowledge pack.
4. Several zips at once: drop them together. Each model is analysed, then the *Analysis package* view opens.
5. Optional: *Download template* → fill `enrichment.json` (by an agent or by hand) → *Upload filled enrichment.json*. The docs are rebuilt with the business descriptions, marked *AI-drafted · review*.

How it fits a locked-down PC: no admin rights, no installs, no .exe. The app is a small web server from Python's standard library bound to `127.0.0.1` only (no firewall prompt, nothing reachable from the network); write requests need a custom header and same origin, and unknown `Host` headers are refused. Analyses are kept in `work/ui-runs/` (git-ignored) and can be deleted in the app. Close the console window to stop. Options: `python app/server.py --port 8765 --data-dir <folder> --no-browser`.

## Analysis package for SharePoint and Agent Builder

An agent in Microsoft 365 Copilot (Agent Builder) can answer questions about all your semantic models if it has them as SharePoint knowledge. Agent Builder reads Word, PDF, PowerPoint, Excel and text files from SharePoint (not Markdown), at most 100 files per agent, and answers from retrieved passages. The package is built for that:

- `Knowledge/00 Catalog.docx` – all models, what each is for, and the cross-model answers computed in advance: measures with the same name but different logic, measures defined identically, tables in several models with column differences, sources used by several models, tables joined differently, errors and warnings per model
- `Knowledge/<Model> - 1 Overview and pages.docx`, `- 2 Data model and sources.docx`, `- 3 Measures.docx` – every heading carries the model name, so answers can say which model they come from
- `Agent-Instructions.txt` – paste into the agent; `README.txt` – setup and update steps
- `Machine-readable/` – model.json, agent brief, enrichment and `portfolio.json` for tools and pipelines (not for the agent)

In the app: *Analysis package* → select models → review overlaps → *Download package*. Command line:

```bash
python3 skills/pbip-explain/scripts/pbip_explain.py package work/model-a work/model-b --out catalog.zip --name "Semantic model catalog"
```

File names are stable, so a rebuilt package can overwrite the SharePoint files and the agent keeps working. 1 + 3 files per model: up to 33 models fit one agent.

## Quick start – command line

1. Save and zip the project as above.
2. Run:

```bash
python3 skills/pbip-explain/scripts/pbip_explain.py run MyReport.zip --out work/my-report
```

3. Open `work/my-report/docs/<Name>-documentation.html`.

No installs: Python 3.9+ standard library only. Works on Windows, macOS and Linux.

## With an agent

`skills/pbip-explain/SKILL.md` is the agent's playbook (Claude Code picks it up via `.claude/skills/`). The agent

1. runs the extraction,
2. drafts business descriptions into `enrichment.json` from the extracted facts (shown as *AI-drafted · review* in the docs; model descriptions always win),
3. rebuilds the docs,
4. answers questions with the query commands.

Other agents can use the knowledge pack as knowledge files; see *Copilot Studio* below.

## Copilot Studio

Two ways to run it there, both built from this repository with

```bash
python3 scripts/build_copilot_skills.py
```

which writes `dist/copilot/`: `pbip-explain.zip`, `agent-instructions.txt`, `agent-instructions-qa.txt` and `build-report.txt` (says what changed since the last build, so only that needs uploading again).

- **A – Q&A agent, no code execution.** Paste `agent-instructions-qa.txt` into the agent's instructions. Per report, extract locally (`pbip_explain.py run <zip> --out work/<name>`), then `python3 scripts/build_copilot_skills.py --knowledge work/<name>` writes `work/<name>/copilot-knowledge/`: the agent brief, the CSVs and the documentation Markdown, each named `<pack>-<file>` so several reports can live in one agent. Upload them under *Knowledge › Add knowledge › Upload files*. `--with-model-json` adds `model.json`.
- **B – agent with code execution.** Upload `pbip-explain.zip` under *Build › Skills › Add skill › Upload a skill* and paste `agent-instructions.txt` into the instructions. Users attach the PBIP zip; the agent runs the tool in its sandbox, answers and hands back the docs and a knowledge zip that feeds mode A.

Copilot-specific text lives only in `copilot/` (`agent-instructions*.md`, `notes/` inserted at the top of `SKILL.md` in the package), never in `skills/`. The build refuses to write anything if a Microsoft host limit is violated; the limits are the same as in the sister project html2pbi.

## Commands

```
pbip_explain.py run     <zip|folder|.pbip> --out <dir>   extract + docs
pbip_explain.py extract <zip|folder|.pbip> --out <dir>   knowledge pack only
pbip_explain.py docs    <dir> [--enrichment file]        rebuild docs (after editing enrichment.json)
pbip_explain.py query   <dir> summary | find <text> | measure <M> | table <T> | column <T[C]> | page <P>
                              | path <A> <B> | impact <M|T[C]|T> | unused | findings
```

## Output

```
work/<name>/
  00-input/                 unpacked zip (data caches *.abf skipped)
  knowledge/
    model.json              all facts (schema: skills/pbip-explain/references/knowledge-schema.md)
    agent-brief.md          compact overview for an LLM
    tables.csv columns.csv measures.csv relationships.csv visuals.csv sources.csv
  enrichment.json           business descriptions (template; filled by an agent or by hand)
  docs/
    <Name>-documentation.html   self-contained, offline, searchable
    <Name>-documentation.md     for wikis / Git (Mermaid ER diagram)
    model-diagram.svg           for slides and Confluence
```

## What it reads

TMDL and model.bim semantic models; PBIR and legacy report.json reports. Details and limits: `skills/pbip-explain/references/limitations.md`.

## Development

- Code: `skills/pbip-explain/scripts/pbipx/` (`tmdl`, `model`, `report`, `dax`, `mquery`, `analysis`, `pack`, `docs`, `diagram`, `query`)
- Synthetic examples: `python3 examples/generate_examples.py` (TMDL + PBIR with every feature the analysis checks; legacy model.bim + report.json)
- Desktop app: `app/server.py` (stdlib HTTP server + JSON API) and `app/static/index.html` (single page, no external assets); launchers `start.bat`, `start.command`
- Package: `pbipx/portfolio.py` (cross-model analysis), `pbipx/package.py` (stdlib .docx writer + package)
- Single file: `python3 scripts/build_single_file.py` after every change to `skills/` or `app/`
- Tests: `python3 tests/test_pbipx.py`, `test_app.py`, `test_package.py`, `test_single_file.py` – must be green before every commit
- Copilot build: `python3 tests/test_build_copilot_skills.py` – builds the packages and checks them against the host limits; must be green after every change to `skills/` or `copilot/`
- `work/` is git-ignored. Real projects are analysed there and never committed.
